# 角落按钮：需求

在「用 VSCode 打开」插件上做增量：把独立浮窗按钮换成一个不挡内容的角落按钮。

## 背景

上一轮试的独立浮窗按钮（`ui.panel` + `ui.shape: "widget"`）实测可用，但**位置不可控**：宿主建窗不传坐标，Electron 把它摆在屏幕正中，正好压住内容；面板窗口也没有移动通道，位置还不持久化。用户要求换到角落里。

## 目标

- 窗口右下角一个常驻小按钮，点一次就打开当前工作目录。
- 按钮只占自己那一小块，**不遮挡也不拦截**按钮之外任何 UI 的点击。
- 输入框右侧按钮与 `/vscode` 命令保持不变。

## 验收

- 有工作目录时：点角落按钮打开 VSCode，toast 提示「已用 VSCode 打开」。
- 没有工作目录时：提示「当前没有工作目录，先打开一个项目。」，且不拉起命令。
- 找不到可用命令时：提示「打不开 VSCode。请确认已安装 Visual Studio Code。」
- 打开过程中按钮显示「打开中」并禁用，重复点击不重复打开；成功后短暂显示「已打开」再复位；失败显示「失败」，原因放进悬停提示。
- 角落按钮之外的界面照常可点、可选中、可滚动。
- 插件卸载后按钮与它所在的层一起消失。

## 右下角按钮带（跨插件约定）

宿主没有「角落」槽位，每个插件都自己往右下角画，位置只能插件之间自己协商。约定：

- 凡是在窗口右下角画常驻按钮的插件，都给按钮加属性 `data-pi-corner-button`（空值），加入同一条按钮带。
- 同一窗口里所有带这个属性的按钮按 **DOM 顺序** 从下往上排：文档里靠前的贴右下角。
- 第 i 颗按钮向上让位 `Σ(下面每颗按钮的高度) + 8px × i`，用 `transform: translateY(-Npx)`，只改绘制不改布局。
- 高度取 `getBoundingClientRect().height`；隐藏（高度为 0）的按钮跳过、不占位。
- 每颗按钮只写自己的内联样式，不碰别家的元素；值没变就不写，免得自己触发自己的 `MutationObserver`。
- 显示按钮时、以及每次 DOM 变动时各重排一次，别的插件出现或消失都能跟上。

## 约束

- 只认一个调用方法（`openWorkspace`），不认识的直接拒绝。
- 不新增网络、文件、剪贴板权限；不声明 `ui.panel`。
- 渲染器模块必须是无构建 ES 模块，不能用 JSX、不能依赖 npm 包（宿主只提供 `react` / `react-dom`）。
- 单次 `plugin.call` 宿主预算 2 秒，因此打开动作必须在拉起进程后立即返回。
- 文案必须 en / zh-CN 两份，界面不留写死的可见文案。

## 不做

- 不改插件 id、命令 id、打开顺序。
- 不做可拖拽、不做位置记忆（宿主不提供）。
- 不做从左下角起的可配置位置：默认右下角，换边只改一行 CSS。
