# 发布到 PI-Desktop 插件中心

整理自官方原始文档（不看网页渲染版，直接读源码）：

- 开发规范源码：`vastsa/PI-Desktop` → `docs/zh-CN/plugin-development.md`
- 市场仓库：`vastsa/pi-desktop-plugins` → `CONTRIBUTING.md`、`README.zh-CN.md`
- 发布 skill 原文：`https://plugins.aiuo.net/skill.md`（MCP：`https://plugins.aiuo.net/mcp`）
- 打包 / 审计脚本：`vastsa/pi-desktop-plugins` → `scripts/pack_plugin.py`、`security_audit.py`、`rebuild_catalog.py`

## 一、两条路，别搞混

| 动作 | 结果 |
|---|---|
| 往 `vastsa/pi-desktop-plugins` 提 PR | 只是把**源码**加进官方仓库，**用户装不到** |
| 在 `plugins.aiuo.net` 提交版本 | 审查 + 管理员审批后才真正上线 |

`plugins.aiuo.net/catalog.json` 是客户端的默认目录源，也是目前唯一受支持的发布渠道。平台负责打包、审查源码、记录 SHA-256，并把 `catalog.json` + `packages/` 镜像到 `AIUO-Net/pi-desktop-plugins` 做 GitHub 备用源（raw 与 CNB 镜像用来兜插件中心不通的网络）。

## 二、发布需要三样东西

1. **打好标签的源码仓库** —— 推送插件并打标签，例如 `v0.3.0`。标签或 commit SHA 就是审查读取的 `sourceRef`。
2. **已绑定的仓库** —— 在控制台「源码仓库」绑定（GitHub App 授权）。绑定是源码审查与目录 source pin 的依据，之后非管理员不能更换。
3. **一个没发布过的版本号** + 发布说明（`releaseNotes`，Markdown，必填）。

`pi.` 和 `demo.` 是保留命名空间，发布需要管理员身份。

## 三、控制台路径

1. 登录 https://plugins.aiuo.net → **我的插件** → **创建插件**：上传包、绑定插件所在仓库、提交。
2. 后续版本在该插件自己的页面提交。

令牌：https://plugins.aiuo.net/console/publish/tokens

## 四、Agent 路径（skill + MCP）

```bash
mkdir -p ~/.agents/skills/pi-plugin-publish
curl -fsSL https://plugins.aiuo.net/skill.md -o ~/.agents/skills/pi-plugin-publish/SKILL.md
```

令牌文件：`~/.pi-desktop/plugin-center.token`（0600）。**不要**放 `$PI_SCRATCH_DIR`，scratch 会随会话删除。

没有令牌时走设备码授权（不要叫用户自己去点网页，要自己开浏览器）：

```bash
curl -sS -X POST https://plugins.aiuo.net/api/v1/device/start \
  -H 'Content-Type: application/json' -d '{"clientName": "pi-desktop"}'
# 取 deviceCode，用 verificationUriComplete 打开系统默认浏览器，把 userCode 给用户核对
curl -sS -X POST https://plugins.aiuo.net/api/v1/device/token \
  -H 'Content-Type: application/json' -d '{"deviceCode": "<deviceCode>"}'
```

### 提交流程（skill 的 fast path）

1. 跑 i18n 门禁，**0 fail**。
2. `list_plugins` —— 验证授权，顺带看 id 是否已存在。
3. 读本地 `manifest.json`，把字段**原样**作为参数发送，`ui` / `contributes` / `activationEvents` / `fs` / `net` 一个都不能漏（漏了宿主报 `PLUGIN_INVALID`，装上也是坏的）。平台会用你发的参数重建 `manifest.json`。
4. git 上已经有 `sourceRef`：commit、push、打 `v<version>` 标签（或用 commit SHA）。
5. `files`：除 `manifest.json` 外的全部运行时文件；跳过 `.git`、`.github`、`test/`、`node_modules`、`*.piplug`、`.DS_Store`。
6. id 已存在 → `submit_version`；否则 `list_repositories` → `create_plugin`（带 `repository`）。
7. `plugin_status` 看一次，报告 id / 版本 / 状态，**停**。等待中的版本不要重复提交。

> skill 明确说：不要先 `pack_plugin`，不要自己 zip 成 `.piplug`，不要重写 `manifest.json`。`create_plugin` / `submit_version` 自己会打包，先 pack 会让载荷翻倍。

## 五、i18n 门禁（最容易卡的一关）

平台会用你发的参数重建 manifest，所以**本地是什么就上架什么**。上传前必须 0 fail：

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | 覆盖 | `i18n.en` 与 `i18n.zh-CN` 各自都有非空 `name`、`description`、`safetyNotes` |
| 2 | 本地化槽位 | `ui.title`、每个 `contributes.views[].title`、`sessionSources[].label`、主题 `label`/`description` 必须是 `{ en, zh-CN }` 且两个都非空；**纯字符串宿主直接拒绝** |
| 3 | 转义 | 发解码后的原文，不要手工预转义。`\\n`、`&amp;`、`<b>` 会原样进目录 |
| 4 | 面板文案 | 面板自带文案表 `en` / `zh-CN` 键一致、占位符一致，插入值只用 `textContent`，**不能用 `innerHTML`** |

跑法（在插件目录里）：

```bash
python3 ~/.agents/skills/pi-plugin-publish/i18n_gate.py   # 或从 skill.md 里抄出脚本
```

## 六、打包约束

- 包根目录必须有 `manifest.json`
- **store-only（未压缩）ZIP**：普通 `zip` 的默认压缩会被安装器拒绝（本仓用 Python `zipfile` + `ZIP_STORED` 打的包可用）
- 不允许符号链接；不允许路径穿越
- 最多 2000 个文件 / 50 MiB
- 宿主端**不会** `npm install`，依赖必须自己打包进插件目录
- 官方脚本：`python3 scripts/pack_plugin.py plugins/<id>`

## 七、安全审查门禁

新增插件或行为变更必须过：

```bash
python3 scripts/security_audit.py --check-packages
```

一票否决：后门、隐藏数据收集 / 外传、远程代码加载、无法解释的混淆、硬编码凭据、持久化、改安全控制、未经确认的破坏性操作。

涉及文件写入 / 删除、网络、凭据、原生二进制、shell/PTY、SSH、后台服务、提示注入、桌面控制的，还要：能力/数据流矩阵、负向路径测试、依赖来源说明、**两名独立维护者复核**。

## 八、PR checklist（往官方仓库提源码时）

- [ ] `id` 唯一
- [ ] 语义化 `version`
- [ ] README 说明「做什么 / 为什么 / 权限」
- [ ] `python3 scripts/pack_plugin.py ...` 成功
- [ ] `python3 scripts/rebuild_catalog.py` 更新了 `catalog.json`
- [ ] catalog 里的包 sha256 与 `.piplug` 一致
- [ ] 用「加载开发插件」和 / 或「安装 .piplug」实测过
- [ ] 源码与包里都没有密钥
- [ ] `security_audit.py --check-packages` 零 blocker

## 九、发布前自检（官方第 10 节）

1. 用稳定的反向域插件 id
2. 语义化版本更新 `version`
3. `engines.piDesktop` 写成真实支持的版本
4. README 记录每个命令、设置、工具输入、权限、外部服务
5. 加 changelog 与许可证
6. 生成的 JS 与资源都构建进插件目录
7. `pi-plugin check` 全部错误清零
8. `pi-plugin pack` 后在干净应用状态安装一次
9. 在发布工件旁边记录打印出来的 SHA-256
